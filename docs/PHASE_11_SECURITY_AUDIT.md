## Cryptographic findings and local changes

1. Python's generic PEM loader accepted SEC1 `EC PRIVATE KEY` in addition to the required PKCS#8 format. Added a shared strict PEM armor/parser that accepts only one unencrypted `BEGIN PRIVATE KEY` P-256 block; exporter and manifest signer now use it. Regression tests reject SEC1, encrypted PKCS#8, and wrong curve.
2. Python `verify_envelope` checked the curve and status but did not require the trust-record algorithm label. It now requires `SHA256withECDSA-P256` and an active/retiring state.
3. Android previously accepted any EC curve with 256-bit field and order. The verifier now compares the complete domain parameters against the standard P-256 constants, avoiding reliance on provider-specific named-curve lookup while loading the pinned trust store and verifying a signature. A synthetic 256-bit non-P-256 regression case confirms that matching field/order widths are insufficient.
4. A fixed test-only public key/signature vector generated by Python is verified by both Python and Android JCA tests (the Android verifier suite reports 11/11 passing). The vector includes no private key. Android's application trust store remains empty, so production updates remain fail-closed.
5. Added a read-only Windows/Python preflight and a production OTA Environment guard. The latter uses a read-only Actions token to check actual main-only branch policies and required reviewer/self-review controls before any signer job can run. It does not access the OTA Secret. The local GitHub audit now explicitly decodes `gh` output as UTF-8, avoiding Windows code-page failures.
